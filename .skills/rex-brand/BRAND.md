# REX Cybersecurity — Brand Foundations

**Status:** Working brand brief
**Last updated:** 29 October 2026

> Items marked **Proposed** are ideas, not finalized decisions. The logo is still a concept and has not been finalized as a production-ready SVG asset set.

## 1. Brand architecture

- **Umbrella / working brand name:** REX Cybersecurity
- **Scope:** Defence, offence, combined security work, education, professional services.
- **Personal vs startup brands:** Connected identities, related visual system, distinct logos.
- **Platforms:** Portfolio, website, LinkedIn, GitHub, technical projects, future products.
- **Logo status:** Abstract symbol + wordmark preferred; no final logo approved.

## 2. Personality and voice

- **Personality (confirmed):** Technical, minimal, trustworthy.
- **Voice (confirmed):** Technical and authoritative. Precise, evidence-led, confident. No unsupported claims, vague hype, or decoration.
- **Content mix (recommended, not yet confirmed):** Technical breakdowns as the core, plus research/insights, educational explainers, professional insights.

## 3. Colour system (confirmed)

| Role | Colour | Hex |
|---|---|---|
| Obsidian / near-black | Primary dark base | `#09090B` |
| Deep indigo | Secondary depth | `#312E81` |
| Blue | Primary accent | `#2563EB` |
| Purple | Secondary accent | `#A855F7` |
| White | Light surface / contrast | `#FFFFFF` |

- Mostly dark; keep light variants for documents, print, light contexts.
- Verify contrast on both dark and light surfaces.
- Use blue and purple deliberately for emphasis, not decoration.

## 4. Typography

| Role | Typeface | Use |
|---|---|---|
| Primary | Space Grotesk | Headings, titles, brand headlines |
| Secondary | Arial | General text, documents, compatibility |
| Technical accent | IBM Plex Mono | Code, terminal labels, IPs, tags, data labels |

Wordmark: IBM Plex Mono preferred for explorations; check spacing and legibility at small sizes.

## 5. Graphic language

Reference sheet: `reference/visual-system-geometric-elements.webp` (user-supplied, 29 Oct 2026). It supersedes the earlier order below where they differ.

**Primary motif:** Diagonal cuts.

**Shapes in preferred order, with frequency (from the sheet):**

| # | Shape | Frequency |
|---|---|---|
| 01 | Triangles | Very frequent |
| 02 | Slanted blocks | Very frequent |
| 03 | Dotted patterns | Frequent |
| 04 | Angles + grids | Frequent |
| 05 | Angled frames | Moderate |
| 06 | Layered panels | Moderate |
| 07 | Hexagon shapes | Additional |
| 08 | Abstract 3D shapes | Occasional |
| 09 | Rhombus / diamond | Rare |
| 10 | Glitch elements | Very rare |
| 11 | Gradient blobs | Very rare |

**Combinations shown:** diagonal cuts + triangles, diagonal cuts + slanted blocks, dotted patterns + grids, hexagons + grids, layered panels + frames, abstract 3D + diagonal cuts, subtle glitch (rare).

**Background patterns:** diagonal, triangle, slanted block, dot grid, grid + angle, hex grid, subtle gradient.

**Use:** social posts, documents, presentations, portfolio. Blue-to-violet gradients on obsidian; restrained, not every motif in every design.

**Image style (confirmed):** Abstract technical graphics, no generic stock cybersecurity imagery.

## 6. Background and theme

Dark-first, light variants required. Logo, wordmark, and graphic language must stay recognizable in both. Ensure contrast for small text, thin lines, monochrome marks.

## 7. Logo requirements

**Direction:** Abstract symbol + wordmark; geometric, avoids literal lock/shield.

**Deliverables (separate SVG files, not a sheet):**
1. Icon-only symbol variations
2. Colour logo, transparent background
3. Monochrome logo
4. Wordmark with coloured **X** (A1-style; not the overall A2 style)
5. Minimal monochrome wordmark (A3-style)
6. Dark and light background versions where needed

**Production checks:** real vector paths (no embedded raster); transparent backgrounds; alignment, spacing, clear space; legibility at favicon/app-icon size; one-colour monochrome; test on dark and light; one clearly named file per variant.

## 8. REX acronym directions

| Direction | Expansion | Status |
|---|---|---|
| Defence | **R**esilience · **E**ngineering · e**X**clusion | **Default** (portfolio, main brand) |
| Offence | **R**econnaissance · **E**xploitation · e**X**ecution | Proposed |
| Both / Purple Team | **R**esearch · **E**ngineering · e**X**ploitation | Proposed |
| Educational | **R**esearch · **E**ducation · e**X**ploration | Per post, when content is educational |
| Professional | **R**eliability · **E**xpertise · e**X**cellence | Per post, when content is professional |

**Usage rule (29 Oct 2026):** Defence is the meaning on the portfolio and the main brand. On social media the expansion changes per post, following the post's content (offence, purple team, educational, professional). Brand interpretations, not industry definitions. "eXclusion" is a deliberate stylization.

## 9. Tagline

Not finalized. Candidates (not selected): "Anticipate. Defend. Prevail.", "Detect. Protect. Evolve." Keep the acronym expansion distinct from any marketing tagline.

## 10. Application

**Priority:** Consistency across all platforms — portfolio/website, LinkedIn/social, GitHub (profile, repos, READMEs, covers), technical reports and presentations, future tools and services. Portfolio is the likely reference point.
